# Cadenza Change Summary Log

## [Commit: d2396e40ce2b3c678bf59a96639067a54941fcdb] - Krishna_Updates

**Date:** 2026-08-25
**Branch:** krishna_updates

This update outlines the full scope of changes integrating the new geometry architecture and interactive frontend.

### 1. Executive Summary
We have fundamentally overhauled Cadenza to be more interactive, resilient, and mathematically sound. We moved **mathematical layout, boolean evaluation, and spatial reasoning out of the LLM and into the deterministic Python geometry engine**, while simultaneously giving the frontend user and the backend agents advanced probing tools to select and interrogate the 3D space directly.

## 2. Shared Contracts & Ledger (`ledger.py`)
The JSON ledger is the communication bridge between the LLM and the geometry engine. We significantly expanded its vocabulary to support native, high-level design intents:
* **Expanded Primitives:** Added schemas for `Cone`, `Sphere`, `Torus`, and `Sketch`.
* **Topological Modifiers:** Added `EdgeFillet` and `EdgeChamfer` allowing the LLM to directly modify edges without spoofing subtractive boolean blocks.
* **Patterning:** Added `LinearPattern` and `CircularPattern` features so arrays can be defined parametrically.
* **Smart Parameters:** 
  * Added `through` and `draft_angle` (taper) to `Cylinder` and `Box`.
  * Added `relative_to` in placement, allowing features to be anchored relative to other features rather than global coordinates.

## 3. Geometry Engine Overhaul (`builder.py`, `plan.py`, `probe.py`)
### Abstracting Math from the LLM
Previously, the LLM had to do precise trigonometry to array holes or position chamfers. Now, it just specifies *intent*.
* **Native Patterning:** The engine dynamically arrays target features (e.g., repeating a single drill hole 8 times around an axis) natively using `build123d`.
* **Primitive Alignment:** Added alignment flags (like `Align.MIN` or `Align.CENTER`) so objects automatically snap to the floor or centerlines without LLM offsets.
* **Robust Revolve & Extrude:** Fixed the revolve logic to accept an arbitrary axis vector and origin. Extrusions now gracefully handle 2D profiles without crashing the 3D boolean subtraction loop.

### The Probing System
* **`probe.py` Introduction:** We built a powerful new backend inspection tool that performs raycasts, BRep boundary evaluation, minimum clearance calculations, and surface area queries on the generated `build123d` shapes.
* **Plumbing:** `geometry_bridge.py` and `service.py` were updated to directly route queries to the new `probe.py` backend (`run_probe_query`), deprecating the legacy point probing mechanisms.

### 3.3. Relative Framing (`frames.py`)
* **Recursive Relativity:** To support the new `relative_to` ledger parameter, `frames.py` was updated so `feature_location` recursively multiplies the location of a feature against its parent's location. This allows features to be positioned relative to other moving components (like holes on a moving arm) rather than global zero.

### 3.4. Provenance and Face Attribution (`provenance.py`)
To support the new geometries and the interactive frontend selection, the face attribution system was vastly expanded:
* **New Spec Matchers:** Added `ConeSpec`, `SphereSpec`, and `TorusSpec` mapping logic.
* **GeomType Probing:** `probe_face` now correctly identifies and extracts geometric metadata (axis, radius, center) for `CONE`, `SPHERE`, and `TORUS` faces generated by `build123d`.
* **Heuristic Scoring:** Added `_cone_score`, `_sphere_score`, and `_torus_score` to reliably map final BRep boundary faces back to the JSON ledger features that created them, even after boolean intersections.
* **Pattern Attribution:** The `surfaces_for` logic now recursively evaluates `linear_pattern` and `circular_pattern`, calculating the transformed `step_loc` for every instance so that picking *any* patterned hole correctly attributes back to the source pattern feature.

## 4. Backend Agents (`machinist.py`, `draftsman.py`, `model_client.py`)
The AI Agents were given eyes and tools to understand the geometry they are building:
* **`geometry_probe` Tool:** The Machinist now has direct access to the probing system. If it needs to know the exact Z-height of a curved face or the distance between two holes to place a new part, it can query the python engine during its thought loop rather than hallucinating the math.
* **Sandbox & Lookups:** Both the **Draftsman** and **Machinist** were granted a `math_sandbox` and `lookup_hardware_dimensions` tool to reliably calculate metric clearances, bolt circles, and fastener tolerances. The `orchestrator.py` handles the new intent-based dispatch with the `AgentCard` structure.

## 5. Web Frontend Updates (`Composer.tsx`, `App.tsx`)
The user interface is no longer a blind chat window.
* **Interactive 3D Selection:** The frontend now supports directly clicking on faces of the generated 3D model.
* **Contextual UI:** When a face is selected, the Composer UI displays the surface type (e.g., "Ø20.0 cylindrical face"), surface area, and precise 3D coordinates.
* **Intent-Driven Prompts:** The chat prompt dynamically updates (e.g., "What should happen to this face?") allowing users to visually select areas and command the AI, bridging the gap between conversational AI and traditional CAD interactions.
* **Deprecation:** Removed the experimental `PointAndSpeak` component in favor of the new robust selection UI.

## 6. Project Infrastructure & Testing
* **Unified Environment:** We updated the `RUNNING.md` to reflect our shift to a unified, top-level `.venv` setup (using `requirements.txt`). Previously, `geometry` and `backend` had disjoint dependencies which caused silent fallbacks; now the whole workspace operates under one kernel.
* **Test Suites:** Added and expanded unit tests across `geometry` and `backend` for `test_gear.py`, `test_vision.py`, and `test_ledger_to_solid.py`.

## 7. How This Improves the Application
1. **Foolproof Reliability:** The LLM is no longer forced to do floating-point math or blind boolean forecasting.
2. **Token Efficiency:** Complex assemblies (like gears with patterned holes) now require ~80% fewer JSON objects in the ledger, speeding up inference and reducing cost.
3. **True Interactivity:** The user can interact with the 3D model visually, and the AI agents can mathematically interrogate their own output to self-correct during generation.
