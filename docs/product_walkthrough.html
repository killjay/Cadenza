Initial product review

This guide describes the frozen review checkpoint through planar face attachments (3B). Make independent is planned and is not part of this checkpoint. Test the same commit throughout a review; development can continue separately.

Ready to exercise

Single parts, separate sources, assembly placement, numeric and targeted prompt edits, source face picking, faded context, supported face attachments, Preview/Apply/Cancel, history and Save/Open.

Still under evaluation

AI interpretation, image accuracy, cold-start performance and user comfort. Selected-edge fillet/chamfer and shell workflows have known gaps. General motion, closed-loop mates and arbitrary complex machines are not supported guarantees.

Recorded checks: 373 broader Python regressions, 46 overlapping focused cases, 109 frontend tests, production build and five grouped native browser checks passed. This is scoped evidence, not a promise that every prompt or CAD operation works.

Run your own interactive copy

Use a separate checkout for human testing. Keep it at the review commit while implementation continues in the development folder. Both backend and frontend are required. In Windows PowerShell, from the repository root:

git rev-parse HEAD
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ./shared -e ./geometry -e ./backend
Copy-Item .env.example .env
# Edit .env locally; never send API keys with feedback.
cd web
npm ci
cd ..
.\.venv\Scripts\python.exe -m uvicorn cadenza_backend.app:app --port 8000

In a second terminal, enter web and run npm run dev. Open the URL Vite prints, normally http://localhost:5173. Use Node 22.12+ or compatible 24.x. The combined Python environment must contain all three packages.

Check http://localhost:8000/health reports real build123d geometry, then actually create a small numeric box: health alone does not prove the native worker can start. Missing AI configuration blocks prompts, but numeric controls can still be tested. Restart the backend after changing provider settings. Save before restarting.

Ordinary UI prompts incur provider usage; the evaluator's spending controls do not cap them. If an operation times out, retain diagnostics and accepted-state screenshots instead of treating the timeout as a successful build. A completely fresh dependency installation on another machine still needs its own smoke check.

01

What your project contains

The model tree, Properties and Assistant have separate roles. Assistant history scrolls independently. Click the active part View control again to return to the whole assembly; selecting another part switches directly. Surrounding assembly geometry is faded and is not a face-picking target.

A model is more than the shape on screen. CADenza keeps an editable description of how the design is constructed, then generates geometry from that description.

Operation
Feature

A block, hole, extrusion or pattern inside a part. A feature has its own parameters and identity.

Definition
Source part

The reusable design of a part: for example, one standoff with a central bore.

Occurrence
Instance

A positioned copy of a source: Left standoff and Right standoff can share the same definition.

Project vocabulary
TermWhat it meansWhy it matters when testing
SubassemblyA reusable group of instances and attachments.Changing its shared definition changes every occurrence of that group.
ProjectThe primary design, its sources and assemblies, and its history.Source view and Project view can show different geometry.
LedgerThe structured JSON record of features, dimensions, references and placements.This is the editable design record, rather than just a mesh.
RevisionA version number identifying accepted design state.Prevents applying a proposal to an outdated design.
STEP / GLBGenerated geometry: STEP for exact CAD inspection/export; GLB for browser display.A visually plausible display is not enough; inspect dimensions and exports too.

A source is not an instance. Creating three source parts does not automatically assemble them. A fresh project can have sources in Parts workspace while Project view remains empty.

02

Three entry routes, one acceptance boundary

The action you choose determines the route. The normal Composer can use the general agent workflow. Explicit creation and editing controls use narrower interpreters. Direct numeric controls skip AI entirely.

Browser
Controls and visual feedback

React manages the UI; Three.js displays the model. A separate browser CAD worker supports STEP inspection and picking.

Backend
Design authority and native geometry

Python manages sessions, AI requests, validation and acceptance. Reused build123d/OCCT worker processes generate the CAD geometry. Explicit project saves use SQLite.

Apply is not Save. Apply accepts an edit in the running session. Save persists the project. Unsaved sessions do not survive a backend restart. Open rebuilds saved geometry at a fresh accepted revision.

03

The agent legend

These are specialized roles, not a group that runs in full for every request. They share a model-client layer; an agent name does not imply a separate permanently running model.

RoleResponsibilityConnected tools / services
CoordinatorRoutes selected-geometry edits toward Machinist; otherwise uses Architect.Deterministic routing code. No model call for this routing decision.
ArchitectInterprets general creation, editing or assembly intent; prepares a parts list for assembly work.Model client and current design context.
EngineerAdds known nominal engineering defaults as context.Local lookup tables. Currently not an AI call.
DraftsmanProposes part features through the general prompt route.Hardware lookup + math tool.
MachinistProposes changes to existing geometry through the general route.Hardware lookup + math tool + geometry probe.
LibrarianInterprets requests for standard catalog parts.Model client, followed by local catalog queries.
AssemblerProposes instances and rigid attachments using available parts.Model client and accepted source/catalog context.
Feature editor interpreterHandles explicit source additions and pinned-feature edits. Also runs in restricted New Part mode.Typed command capabilities; no registered agent tools.
Assembly editor interpreterHandles an explicitly selected assembly, instance or attachment target.Typed assembly commands; no registered agent tools.
Sketch editor interpreterInterprets supported requests against a sketch draft.Restricted sketch actions; no registered agent tools.

The targeted part, source and assembly routes permit at most one interpretation request per submission. The general workflow can involve several agent calls and bounded repair attempts. Provider/model choices come from configuration.

General creation: Architect → Draftsman → build/check → preview
General selected edit: selection resolution → Machinist → build/check → preview
General assembly: Architect → Librarian branch → Assembler → build/check → preview

The Librarian branch can skip a model call when no standard parts need sourcing. The targeted UI routes bypass this general sequence.

Which tool connects to what?

There are three registered model-callable tools. Building, saving and accepting changes are application services with their own rules; they are not freely available tools for every agent.

05

Walk through a design

Use these scenarios in order. All dimensions below are millimetres. Suggested prompts exercise the current routes; exact AI output must still be reviewed.

Scenario 1 · Single source

Create a mounting plate

Open Parts workspace → New Part. Name it Mounting plate, choose Create with AI, then submit:

Create one rectangular plate, 80 mm long along X, 50 mm wide along Y, and 8 mm thick. Centre it in X and Y, with its bottom at Z=0. Add one centred diameter-10 mm through hole opening from the top at Z=8. Use zero rotation.

New Part interpreter → supported creation commands → native build → preview → your decision

The interpreter receives an empty creation context. The server assigns identities, validates the proposal and builds the geometry. This route initially supports box, cylinder and hole operations; dependent features can be added after Apply.

Check: plate dimensions, hole diameter and through-hole behavior. Cancel should leave no accepted new part. Apply should create the source. Choose View Mounting plate afterward; Project view may still be empty.

Typing a creation request into the ordinary Composer without a special target instead uses Architect → Draftsman.

Scenario 2 · Controlled edits

Change a dimension, then add a feature

Scroll over a numeric field and confirm the value does not change accidentally. Use the visible preview/Apply controls rather than relying on Enter. First change Stock length from 80 to 100 using its numeric control. Preview and Cancel. Repeat and Apply. This uses no AI call.

Next select the existing hole feature and choose Edit with AI:

Change only this hole’s diameter from 10 mm to 12 mm. Keep it centred and through the plate. Preserve every other feature and dimension.

To add a feature, choose Add with AI on the source:

Add a second diameter-6 mm through hole at source-local X=25, Y=0, opening at Z=8. Preserve the existing hole and stock dimensions.

Pinned source / feature → Feature editor interpreter → typed commands → preview

Check: an edit modifies the selected feature; an addition creates a new feature. The original hole remains centred. Other dimensions and features stay unchanged. Try Undo and Redo after Apply.

A face selection followed by a general prompt uses selection resolution and Machinist instead. The chosen UI target is part of your test input.

Scenario 3 · Multiple sources

Build the parts before assembling them

In a fresh project, create and accept these three sources separately through New Part. Use source-local centring, base Z=0 and zero rotation; bores open from each part’s top.

SourceDefinition
Base plate160 × 100 × 10 box.
Standoff20 × 20 × 30 box with a centred Ø8 through bore.
Cap40 × 30 × 8 box with a centred Ø8 through bore.
Check: all three sources appear in Parts workspace. Each source view shows the correct part. Creating one source preserves the earlier sources. You have definitions at this point, not a placed assembly.
Scenario 4 · Assembly and reuse

Place two occurrences of one source

Continue from Scenario 3, with an eligible empty primary design. Return to Project view and use the assembly controls or Add to assembly with AI.

Create a rigidly positioned assembly from the existing sources. Add Base plate as “Base” at (0,0,0). Add Standoff as “Left standoff” at (-50,0,10), and another instance of the same source as “Right standoff” at (50,0,10). Use zero rotation for every instance. Do not add attachment joints yet.

Assembly editor interpreter → existing source references + placements → whole-design build and interference checks → preview

This request uses Base plate and Standoff. Cap remains an available, unused source. Explicit placements do not create attachment joints.

Project assembly ├─ Base → Base plate source ├─ Left standoff → Standoff source └─ Right standoff → the same Standoff source
Your actionExpected result
Move Right standoff X=50 → 55Only that occurrence moves.
Change Standoff source width 20 → 24Both occurrences become wider.
Edit a reused subassembly definitionEvery occurrence of that group changes.
Check: distinct instance names and positions, one shared Standoff definition, and the correct scope of each edit. Making only one occurrence geometrically different requires independent-source functionality that this targeted editor does not currently provide.
Scenario 5 · Protection and recovery

Use the prepared locating fixture

Use your own saved test assembly. If your reviewer package includes Layout A - Review copy, it provides five sources and a repeated module; this named fixture is not automatically installed by cloning the repository.

Attached Cap

Attempt to move it without authorizing detachment. Expect refusal, not silent removal of its attachment.

Overlapping modules

Place Right module directly over Left module. Expect interference rejection and an unchanged accepted design.

Then make a valid edit, Apply, Save, open another project and reopen the saved one. Names, features, placements and history should survive. Geometry is rebuilt at a fresh revision.

Check: rejected operations do not mutate accepted state. Preview is not acceptance, and acceptance is not persistence. Save before a backend restart.
Additional test · Drawing input

Ask the application to acknowledge uncertainty

Attach a dimensioned drawing while creating a part or editing an explicitly selected target. The image follows that route to an image-capable provider. It is interpretation evidence, not an exact measurement source.

Check: intentionally omit one critical dimension. An appropriate clarification question is a correct result. Confidently inventing that dimension is a failure.
New review case: connected editing

Make selected faces stay together

Use a fresh assembly with a 100 × 60 × 15 box base, two instances of a Ø20 × 30 cylinder spacer at (-30,0,15) and (30,0,15), and a 100 × 60 × 8 cap at (0,0,45). Sources are centred in X/Y with their bottoms at Z=0; all rotations are zero. Create and place these sources before attaching them.

  1. Select the assembly, then Properties → Rigid attachments → Attach faces.
  2. Choose Base as fixed and LeftSpacer as following. Pick the base top near (-30,0,15), then the spacer bottom centre. Use selected face at each step, Preview, inspect, Apply.
  3. Repeat for RightSpacer at X=30. Attach Cap to LeftSpacer's top using the matching cap bottom point near X=-30. One driving attachment per child is supported.
  4. Change base thickness from 15 to 12. Both spacers and the cap should move down by 3 mm, retaining their X/Y positions. Check declared contact evidence; Cancel once, then repeat and Apply.
  5. Exercise Undo/Redo, Save/Open, and an invalid shrink that moves an anchor outside its face. A rejected edit must leave accepted geometry unchanged.
Scope: declared contacts are checked, not every possible fit or clearance. Existing coordinate joints do not automatically convert. Face attachments are authored manually in this release; targeted AI source edits still rebuild and verify them.
06

What to expect today

Understanding an assembly request is not the same as generating every missing part. Architect can produce a parts list, but Assembler is instructed to request missing custom sources. A complete custom machine from one prompt remains a capability to develop and evaluate further.

Targeted changes are deliberately bounded

New Part creates one source. A source-only AI request adds features; modifying an existing feature requires selecting it. Assembly editing does not mix source geometry changes with instance changes.

Supported attachments are rigid

Explicit box-face and cylinder-end-face attachments now track source edits and verify finite contact. Old coordinate attachments retain their original behavior. Motion joints, arbitrary-face mates and closed loops remain unsupported. A request for unsupported behavior should explain the limit or ask a question.

Nominal hardware is not certification

Engineering defaults and catalog geometry are prototype capabilities. A tool result does not establish manufacturing or standards compliance.

Geometry success still needs review

Building a valid solid does not prove that every sentence or image detail was interpreted correctly. Check intent, dimensions and editing scope independently.

07

Test with a clear expectation

Follow this order: single-source controls → targeted additions/edits → multiple sources → assembly placement → shared-source changes → rejection and recovery. It makes a failure easier to locate.

These checkboxes are a reading aid only; their state is not saved. Use the linked review worksheet or retain your own notes.

Diagnostics link requests with relevant model, build and decision evidence, subject to configured capture and retention limits. They do not automatically record a complete visual movie; screenshots remain useful.

Capture each result: record the commit from git rev-parse HEAD, browser/OS, selected source or occurrence, exact prompt or numeric action, expected result, actual result and before/preview/after screenshots. Mark Pass, Fail or Unclear. Check Apply, Cancel and reopening separately.

Use the bottom status bar: Diagnostics → choose the relevant session → Download diagnostics. Include the ZIP and a saved test project when appropriate. Review diagnostics before sharing: they may contain design and prompt content. Never include your .env or API key. Report AI interpretation failures separately from geometry, UI, persistence or startup failures.
